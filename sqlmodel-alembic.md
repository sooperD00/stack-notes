# SQLModel and Alembic

## Autogenerate leaves out `import sqlmodel`
- Symptom: a generated migration fails on SQLModel column types (enum columns)
- Rule: open every autogenerated migration and add `import sqlmodel` at the top if it's missing. Let autogenerate write the file so Alembic owns the revision ID; edit inside it.
- Seen: application-pipeline, 2026 · verified

## `.exec()` vs `.execute()`
- Symptom: `AttributeError: ... has no attribute 'exec'`
- Rule: SQLModel's `Session.exec()` is its convenience method. SQLAlchemy's `AsyncSession` (`sqlalchemy.ext.asyncio`) has only `.execute()`. SQLModel ships its own `AsyncSession` (`sqlmodel.ext.asyncio.session`) with `.exec()`. Check which one the project imports before writing either.
- Seen: Nicole's notes · the SQLModel AsyncSession half is unverified

## A suite on SQLite can't see Postgres failures
- Symptom: tests pass, and production rejects the write
- Rule: when tests run on SQLite and production runs Postgres, a green suite proves the logic, not that Postgres accepts the writes. Anything type- or constraint-sensitive (timezone-aware timestamps, enums, JSONB) gets a check against Postgres.
- Seen: application-pipeline, 2026-09 · verified
